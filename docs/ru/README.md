# 🔐 2FA

Система управления ключами двухфакторной аутентификации на базе Cloudflare Workers. Бесплатное развёртывание, глобальное ускорение и поддержка работы офлайн через PWA.

**Основные возможности:** Автоматическая генерация кодов TOTP/HOTP · Добавление ключей через сканирование QR-кода, распознавание изображения, вставку снимка экрана или перетаскивание изображения · Хранение с шифрованием AES-GCM, 256 бит · Массовый импорт из Google Authenticator, Aegis, 2FAS, Bitwarden и других приложений · Экспорт в разные форматы (TXT/JSON/CSV/HTML/QR-коды миграции Google) · Автоматическое резервное копирование и восстановление · Синхронизация удалённых резервных копий через WebDAV/S3/OneDrive/Google Drive · Настройки безопасности, синхронизации и предпочтений · 15 языков во всём проекте (автоопределение или ручной выбор) · Светлая, тёмная и системная темы · Адаптивный интерфейс в стиле Fluent 2

Веб-приложение, расширения браузера, первоначальная настройка, публичные страницы OTP, сообщения API и документы резервных копий поддерживают упрощённый китайский, традиционный китайский, английский, японский, корейский, немецкий, французский, испанский, португальский (Бразилия), итальянский, русский, турецкий, индонезийский, вьетнамский и тайский языки. Интерфейс использует язык браузера или выбранный вручную язык; если язык браузера не поддерживается, используется английский. Резервные копии CSV/HTML можно импортировать независимо от языка интерфейса.

## 🧩 Расширение браузера

Установите 2FA Verification Assistant: **[Chrome Web Store](https://chromewebstore.google.com/detail/2fa-%E9%AA%8C%E8%AF%81%E5%8A%A9%E6%89%8B/lifeiloiefdlbohelpjajdbopeocalhl)** · **[Microsoft Edge Add-ons](https://microsoftedge.microsoft.com/addons/detail/kmchncmoddhdlbpfoejeahdjhieghklm)** · **[Firefox Add-ons](https://addons.mozilla.org/zh-CN/firefox/addon/2fa-%E9%AA%8C%E8%AF%81%E5%8A%A9%E6%89%8B/)**.

Откройте ссылку установки в соответствующем браузере. После установки укажите URL своего экземпляра 2FA в настройках расширения и войдите в этот экземпляр в том же браузере, чтобы просматривать, копировать и подставлять коды TOTP. Для автоматического заполнения нужно разрешение для каждого сайта; его можно выдать при первом заполнении кода на этом сайте. Расширению нужен развёрнутый экземпляр этого проекта; его интерфейс поддерживает перечисленные выше 15 языков. Для Firefox на компьютере и Android требуется версия 153 или новее и обычные вкладки; вкладки в контейнерах на компьютере и приватные вкладки на обеих платформах не поддерживаются. Firefox для Android поддерживается начиная с версии 1.2.0 в магазине дополнений, но пока не проверен на физическом устройстве. Firefox для Android не предоставляет сочетания клавиш для расширений.

## 🚀 Быстрое развёртывание

### Онлайн-демонстрация

Откройте демонстрационный сайт (пароль `2fa-Demo.`): **[https://2fa-dev.wzf.workers.dev](https://2fa-dev.wzf.workers.dev)**

### Развёртывание одним нажатием (рекомендуется)

[![Развернуть на Cloudflare Workers](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/wuzf/2fa)

> Рекомендуется развёртывание одним нажатием. Всем пользователям следует обновлять существующую установку через рабочий процесс **Sync Upstream**. Не обновляйте приложение путём удаления Worker, удаления репозитория или переустановки.

1. Нажмите кнопку выше, войдите через GitHub и предоставьте разрешение
2. Войдите в свою учётную запись Cloudflare, нажмите **Deploy** и дождитесь завершения развёртывания (хранилище KV создаётся автоматически)
3. Откройте URL Workers, предоставленный Cloudflare, **задайте пароль администратора** и начните пользоваться приложением

> Автоматическая сборка из Git использует `wrangler.toml` непосредственно из репозитория. В текущей конфигурации явно объявлен `SECRETS_KV`: при первом развёртывании Wrangler автоматически создаёт необходимое хранилище KV, а при последующих продолжает использовать ресурс, привязанный к текущему Worker.
> Если вы вручную настраиваете команды сборки из Git в панели Cloudflare, **используйте `npm run deploy` в качестве команды развёртывания, а не прямой вызов `npx wrangler deploy`**, чтобы сохранить подстановку версии и соответствовать стандартной команде развёртывания репозитория.

#### Рекомендуется: включить шифрование данных

После развёртывания добавьте Secret с именем `ENCRYPTION_KEY` в разделе **Cloudflare Dashboard → Worker → Settings → Variables**:

```bash
# Создайте ключ шифрования (выберите одну из команд)
openssl rand -base64 32
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

> `ENCRYPTION_KEY` — главный ключ для расшифровки существующих данных. **Рекомендуется его настроить**, если вы сразу сохраните исходное значение в менеджере паролей, офлайн-копии или другом безопасном месте.
>
> Если вы не можете гарантировать сохранность исходного значения, **лучше вообще не задавать ключ, чем задать его и потерять**:
>
> - После настройки: список секретов, автоматические резервные копии и учётные данные WebDAV/S3/OneDrive/Google Drive шифруются
> - При потере: Cloudflare больше не покажет исходное значение; существующие зашифрованные данные и резервные копии нельзя будет прочитать или восстановить
> - Текущее поведение: если обнаружены зашифрованные данные, но `ENCRYPTION_KEY` отсутствует, система блокирует чтение и запись, чтобы предотвратить случайную перезапись старых данных

#### Обновление версий

Развёртывание одним нажатием создаёт независимый репозиторий (не Fork). Обновления выполняются в существующей установке через рабочий процесс **Sync Upstream**.

> ⚠️ **Всегда создавайте резервную копию данных перед обновлением**: перед обновлением версии экспортируйте текущие данные через **Массовый экспорт** или **Восстановление конфигурации → Экспорт резервной копии**, чтобы избежать потери данных в случае сбоя.

1. Откройте репозиторий 2fa, созданный в вашей учётной записи GitHub при развёртывании одним нажатием
2. Перейдите в **Actions** → **Sync Upstream**
3. Нажмите **Run workflow**, оставьте ветку исходного репозитория по умолчанию — `main` — и запустите новое выполнение
4. Дождитесь завершения синхронизации и автоматического развёртывания Cloudflare, затем обновите страницу приложения

Рабочий процесс автоматически сохраняет имя Worker, привязки KV и общие настройки развёртывания вашего репозитория, затем повторно развёртывает **тот же Worker**. Существующие файлы рабочих процессов в репозитории также сохраняются.

> **Если Sync Upstream отсутствует**: при развёртывании одним нажатием папка `.github/workflows` не копируется при импорте репозитория, поэтому в новом репозитории нет рабочих процессов и перед первым обновлением нужно добавить эту точку входа. Замените `OWNER/REPO` в ссылке ниже на свой репозиторий (например, `alice/2fa`) и откройте её в браузере. GitHub заполнит имя и содержимое файла; нажмите **Commit changes**:
>
> ```text
> https://github.com/OWNER/REPO/new/main?filename=.github/workflows/sync-upstream.yml&value=%23%20Save%20as%20.github%2Fworkflows%2Fsync-upstream.yml%20in%20your%20repository.%0A%23%20The%20upgrade%20steps%20come%20from%20wuzf%2F2fa%2C%20so%20this%20file%20never%20needs%20updating.%0Aname%3A%20Sync%20Upstream%0A%0Aon%3A%0A%20%20workflow_dispatch%3A%0A%20%20%20%20inputs%3A%0A%20%20%20%20%20%20upstream_ref%3A%0A%20%20%20%20%20%20%20%20description%3A%20Upstream%20branch%20or%20tag%20to%20sync%0A%20%20%20%20%20%20%20%20required%3A%20false%0A%20%20%20%20%20%20%20%20default%3A%20main%0A%0Apermissions%3A%0A%20%20contents%3A%20write%0A%0Ajobs%3A%0A%20%20sync%3A%0A%20%20%20%20uses%3A%20wuzf%2F2fa%2F.github%2Fworkflows%2Fsync-upstream.yml%40main%0A%20%20%20%20with%3A%0A%20%20%20%20%20%20upstream_ref%3A%20%24%7B%7B%20inputs.upstream_ref%20%7D%7D%0A
> ```
>
> Можно также самостоятельно создать `.github/workflows/sync-upstream.yml` и скопировать содержимое из <https://github.com/wuzf/2fa/blob/main/.github/sync-upstream-entry.yml>. Точка входа занимает всего несколько строк, а шаги обновления берутся из исходного репозитория, поэтому её никогда не нужно менять. Затем выполните описанные выше шаги обновления.

> **Если предыдущее обновление завершилось ошибкой `without workflows permission`**: после публикации исправления в ветке `main` исходного репозитория существующие рабочие процессы **Sync Upstream**, содержащие шаг автоматического объединения конфигурации развёртывания, смогут выполнить обновление по инструкции выше без правки YAML и настройки PAT. Запустите новое выполнение с `main`; старые теги выпусков не содержат исправления. В остальных случаях см. [устранение проблем при обновлении](../DEPLOYMENT.md#升级故障排查) (на китайском языке).

Этот способ не затрагивает существующие Workers, привязки KV и Secrets. **Если вы уже настроили `ENCRYPTION_KEY`, повторно вводить её при обновлении не нужно; если не настроили, вы всё равно можете использовать этот способ обновления.**

> ⚠️ `ENCRYPTION_KEY` — главный ключ для расшифровки существующих данных. Обязательно сохраните его в менеджере паролей при создании. Значения Cloudflare Secrets нельзя просмотреть после сохранения; обычные обновления не требуют повторного ввода, но если удалить ключ, не сохранив исходное значение, восстановить существующие зашифрованные данные не удастся.

> ⚠️ **Откат к версии ниже 1.8.0**: начиная с 1.8.0, приращения счётчиков HOTP хранятся отдельно от основных данных. Перед откатом один раз вызовите конечную точку API для уплотнения данных, чтобы записать счётчики обратно; иначе счётчики HOTP вернутся к значениям на момент обновления. См. [инструкцию по откату](../DEPLOYMENT.md#回滚到-180-之前的版本) (на китайском языке). Установок, использующих только TOTP, это не касается.

#### Проверка результата объединения

Рабочий процесс `Sync Upstream` предназначен для выполнения обновлений **в том же репозитории и на том же Worker**. Теперь он автоматически объединяет `wrangler.toml` и показывает в сводке отличия от исходного репозитория, чтобы вы могли проверить, какие значения взяты из конфигурации вашего развёртывания:

1. Проверьте различия `wrangler.toml` в сводке выполнения GitHub Actions
2. Откройте `wrangler.toml` в своём репозитории
3. Убедитесь, что имя Worker, привязки KV, маршруты и существующие настройки развёртывания остались корректными
4. Если вы поддерживаете специфические настройки `wrangler.toml`, при необходимости внесите их дополнительными коммитами

> Если Cloudflare не запускает повторное развёртывание автоматически, откройте страницу **Deployments** и повторно разверните последний коммит текущего репозитория — не удаляйте установку и не устанавливайте её заново.

## 📖 Руководство пользователя

### Добавление ключей

Нажмите плавающую кнопку **➕** в правом нижнем углу:

- **Сканировать QR-код** — Сканирование QR-кодов 2FA камерой с автоматическим заполнением
- **Выбрать изображение** — Загрузка снимка экрана с QR-кодом и автоматическое распознавание
- **Вставить снимок экрана** — Ctrl+V для вставки снимка QR-кода из буфера обмена (удобно на компьютерах без камеры)
- **Перетащить изображение** — Перетаскивание изображения QR-кода прямо в диалоговое окно для автоматического распознавания
- **Добавить вручную** — Ввод названия сервиса и секрета Base32 (раскройте дополнительные настройки, чтобы изменить число цифр, период и алгоритм)

### Повседневное использование

- **Копирование кода**: нажмите непосредственно на цифры кода
- **Управление ключами**: нажмите **⋯** в правом верхнем углу карточки → Показать QR-код / Копировать URI / Копировать ссылку на страницу / Изменить / Удалить
- **Поиск**: поиск в реальном времени по названию сервиса или учётной записи в верхней строке поиска
- **Умная группировка**: автоматическая группировка связанных сервисов и нескольких учётных записей с возможностью вернуться к обычному списку
- **Сортировка**: по времени добавления или названию
- **Тема**: плавающая кнопка → **Настройки → Предпочтения → Режим темы**, затем выберите светлую, тёмную или системную тему

### Массовый импорт

Нажмите плавающую кнопку → **📥 Массовый импорт**. Поддерживается импорт из файла или вставка текста.

**Совместимые форматы:**

| Источник               | Формат                                   |
| ---------------------- | ---------------------------------------- |
| Универсальный          | Текст URI `otpauth://` (TXT), CSV, HTML  |
| Google Authenticator   | QR-код миграции (`otpauth-migration://`) |
| Aegis                  | Файл экспорта JSON                       |
| 2FAS                   | Файл экспорта `.2fas`                    |
| Bitwarden              | Экспорт JSON или CSV из Authenticator    |
| LastPass Authenticator | Файл экспорта JSON                       |
| andOTP                 | Файл экспорта JSON                       |
| Ente Auth              | Файл экспорта                            |

### Массовый экспорт

Нажмите плавающую кнопку → **📤 Массовый экспорт**. Поддерживаются форматы TXT, JSON, CSV и HTML, а также создание **QR-кодов миграции Google Authenticator** (их можно отсканировать для прямого импорта).
При наличии сети стандартный экспорт TXT / JSON / CSV / HTML преимущественно использует единый серверный формат и автоматически переходит на совместимый локальный экспорт в офлайн-режиме или при слишком большом теле запроса.

### Резервное копирование и восстановление

Система автоматически создаёт резервные копии (при изменении данных и во время ежедневной проверки по расписанию), сохраняя последние 100 копий (количество меняется в настройках).
Новые файлы резервных копий используют параметр **Настройки → Формат экспорта по умолчанию**. Автоматические удалённые резервные копии имеют такое же расширение (`txt`, `json`, `csv` или `html`).

Нажмите плавающую кнопку → **🔄 Восстановление конфигурации**, чтобы просмотреть список резервных копий, открыть предварительный просмотр содержимого, восстановить или экспортировать данные; также можно загрузить файл `backup_*.(txt|json|csv|html)`, скачанный из WebDAV/S3/OneDrive/Google Drive, для предварительного просмотра и восстановления.

#### Удалённое резервное копирование

Поддерживается синхронизация резервных копий с удалённым хранилищем с автоматической отправкой при изменении данных и возможностью настроить несколько мест назначения:

- **WebDAV** — Поддерживаются облачные диски и собственные сервисы со стандартным протоколом WebDAV (⚠️ сервисы за прокси Cloudflare, например Nutstore/jianguoyun, не поддерживаются: они вызывают ошибки зацикливания 520)
- **S3-совместимое хранилище** — Поддерживаются AWS S3, Cloudflare R2, MinIO, Alibaba Cloud OSS и другие S3-совместимые сервисы
- **OneDrive** — После авторизации через Microsoft OAuth резервные копии записываются во вложенную папку внутри выделенной папки приложения в OneDrive
- **Google Drive** — После авторизации через Google OAuth резервные копии записываются в настроенную папку Google Drive

Добавляйте и настраивайте места назначения удалённых резервных копий в разделе **Настройки → Настройки синхронизации**.

Удалённые резервные копии содержат те же данные, которые приложение создаёт для резервного копирования. Если при создании копии была настроена `ENCRYPTION_KEY`, удалённый файл тоже содержит зашифрованные данные; для его восстановления необходимо сохранить тот же ключ `ENCRYPTION_KEY` в Worker.

Подробная инструкция: [Настройка облачных дисков](../CLOUD_DRIVE_SETUP.md) (пока на китайском языке).

### Настройки

Нажмите плавающую кнопку → **⚙️ Настройки**:

- **Изменить пароль** — Изменение пароля администратора
- **Режим темы** — Выбор светлой, тёмной или системной темы
- **Анимация смены кода** — Отключение анимации или выбор эффекта потока, переворота либо прожектора
- **Срок действия входа** — Настройка срока действия JWT
- **Формат экспорта по умолчанию** — Определяет стандартный формат экспорта и расширение новых резервных копий, включая автоматические удалённые копии
- **Количество хранимых резервных копий** — Настройка числа сохраняемых автоматических резервных копий
- **Удалённое резервное копирование** — Настройка мест назначения WebDAV/S3/OneDrive/Google Drive
- **Выйти** — Удаление cookie текущего сеанса и локального кэша одним нажатием; локальная очистка работает даже при недоступном сервере

### Установка как мобильного приложения (PWA)

- **iOS**: откройте в Safari → кнопка «Поделиться» → «На экран Домой»
- **Android**: откройте в Chrome → меню (⋮) → «Добавить на главный экран»

После установки приложение работает в полноэкранном режиме как обычное мобильное приложение и поддерживает доступ офлайн.

### Подстановка TOTP в Chrome / Edge / Firefox

Нажмите значок расширения, чтобы выбрать учётную запись, или используйте `Ctrl+Shift+U`, чтобы подставить текущий TOTP для ранее привязанной учётной записи. После выдачи разрешения сайту расширение может автоматически обнаруживать и заполнять на нём поля кода; при нескольких совпадениях появляется выбор учётной записи. Поддерживается одно поле или 6/8 отдельных полей для цифр; расширение не отправляет форму.

После входа в экземпляр 2FA в том же профиле браузера и предоставления доступа к экземпляру его вкладку можно закрыть. По умолчанию расширение читает секреты через действующий сеанс и вычисляет коды в фоновой памяти для каждой задачи; по истечении сеанса войдите снова. При явном включении офлайн-режима сохраняется отдельный локальный кэш секретов, чтобы коды оставались доступными без сети и без открытой вкладки экземпляра. У кэша нет дополнительного шифрования паролем. Авторизованный код расширения может читать весь список секретов, но исходные секретные ключи никогда не передаются во всплывающее окно расширения или на целевой сайт. Поддерживаются поля в открытом Shadow DOM и iframe того же источника; HOTP, iframe другого источника, закрытый Shadow DOM и приватный просмотр не поддерживаются.

См. [руководство по установке и использованию](../BROWSER_EXTENSION.md), [уведомление о конфиденциальности Chrome / Edge](../../extension/PRIVACY.md) и [уведомление о конфиденциальности Firefox](../../extension/PRIVACY_FIREFOX.md) (пока на китайском языке).

## 🔒 Безопасность

- **Пароль**: хеш PBKDF2-SHA256 с солью (100 000 итераций), JWT хранится в cookie с атрибутами HttpOnly + Secure + SameSite=Strict
- **Шифрование данных**: при настроенной `ENCRYPTION_KEY` все секреты, резервные копии и учётные данные WebDAV/S3/OneDrive/Google Drive шифруются AES-GCM с ключом 256 бит; обязательно сохраните исходный ключ — при его потере расшифровка данных невозможна
- **Передача данных**: HTTPS для всех соединений, TLS 1.2+
- **Конфиденциальность**: OTP создаются на стороне клиента, данные об использовании не собираются, исходный код полностью открыт
- **Срок действия входа**: по умолчанию 30 дней, изменяется в настройках и автоматически продлевается при активном использовании (если осталось менее 7 дней)

## 🔗 Публичный API OTP

Создавайте коды проверки непосредственно через URL без входа в систему:

```
https://your-worker.workers.dev/otp/YOUR_SECRET_KEY
https://your-worker.workers.dev/otp/YOUR_SECRET_KEY?digits=8&period=60
https://your-worker.workers.dev/otp/YOUR_SECRET_KEY?type=hotp&counter=5
```

Параметры: `type` (totp/hotp), `digits` (6/8), `period` (30/60/120), `algorithm` (sha1/sha256/sha512), `counter` (для HOTP)

Страницы TOTP показывают текущий и следующий коды, каждый из которых можно скопировать, и обновляются на месте по окончании периода. Страницы HOTP используют счётчик, указанный в ссылке; копирование не увеличивает его.
