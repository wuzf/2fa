# v1.13.0：默认显示方式、导入与升级修复

本次新增默认显示方式设置，修复 JSON 导入时服务名和账户被改写、Sync Upstream 合并部署配置时遗漏或误改内容的问题，并改善首页加载。随本版本提供浏览器扩展 `1.3.0`，增强验证器输入框识别。

## 默认显示方式

- 在「设置 → 偏好设置 → 默认显示方式」中，可选择「记住上次选择」「智能聚合」或「全部平铺」。设置立即生效，并用于之后的刷新和重新打开。
- 固定显示方式后，右上角菜单仍可临时切换视图；选择「记住上次选择」时，会继续使用当前显示方式。这项偏好仅保存在当前浏览器。
- 修复首页先显示缓存账户时没有应用已保存视图和排序的问题。现在首次显示就使用保存的选择，离线打开也不会先显示错误的视图。
- 登录后读取的语言与当前语言相同时，不再重复重绘整个账户列表，减少卡片重建和验证码计算。
- 首页移除校时状态横幅和「重新校时」按钮，时间校准由后台自动处理；恢复联网、回到页面和定时校准仍会更新验证码所用的时间。

## JSON 导入

- 本项目 JSON 导出再批量导入时，服务名和账户字段直接保留，不再经过 OTPAuth 标签拆分。例如，服务名 `GitHub`、账户为空时仍保持空账户；服务名 `ACME:Work`、账户 `alice` 也不再被拆成 `ACME` 和 `Work:alice`。
- 支持保留这些字段中的冒号、百分号、中文等字符。显式为空的账户不会被旧格式的 `label` 字段覆盖。
- TOTP 周期和 HOTP 计数器按类型处理，保留有效的 OTP 参数；与类型无关的字段沿用原导入规则，避免旧记录因 HOTP 周期或 TOTP 计数器的无关值被拒绝。
- 原生 OTPAuth 和其他验证器 JSON 的解析路径保持原有行为。本次修复不会自动纠正以前已经导入的名称和账户，请对照来源数据检查并按需编辑。

## 部署配置合并

- Sync Upstream 识别带行尾注释、空白或引号的 TOML 表头，正确保留其下的 KV ID、Cron、变量和支持的开发环境配置。例如，`[[kv_namespaces]] # production` 不再因表头带注释而丢失原 KV ID。
- 按完整赋值读取多行字符串、数组等值，不再把多行变量截断；变量中的 `#`、`=` 或看似配置的文本会保留在原值中。
- 按实际配置位置替换 Worker 名称和路由，避免误改 `build.command` 等多行字符串中相同的 `name = ...` 或 `routes = ...` 文本。多个 KV 绑定也按真实的 `binding` 值识别，不会选中注释或字符串里的示例。
- 本次仍沿用原来的配置保留范围，不是对任意本地定制配置或源码的通用合并。升级前保留原配置，同步后检查差异和实际绑定；如果旧同步已经丢失配置，需要从原配置或 Cloudflare 现有绑定中恢复。

## 浏览器扩展 1.3.0

- 修复带圆角 `clip-path: inset(... round ...)` 的对话框中，验证码框被误判为不可见而无法填充的问题。
- 输入框只写「Code」「Enter code」时，附近有明确验证器说明、输入限定为 6 或 8 位且没有短信或邮件迹象，便可直接识别；已授权的网站也可自动填充。存在发送、重发、倒计时等迹象时仍保留原有的人工确认路径。
- 扩展权限与网站授权流程没有变化。完整说明及安装包信息见[扩展 1.3.0 更新说明](https://github.com/wuzf/2fa/blob/v1.13.0/docs/releases/extension-v1.3.0.md)。商店版本以各商店实际发布进度为准。

## 升级与回滚

1. 升级前导出并保存当前账户数据，保留原 `ENCRYPTION_KEY`、Worker 名称和 KV 绑定。
2. 一键部署用户在 **Actions → Sync Upstream → Run workflow** 选择 `v1.13.0`，等待源码同步及 Cloudflare 构建完成；还没有入口时，按[升级指南](https://github.com/wuzf/2fa/blob/v1.13.0/docs/DEPLOYMENT.md#升级指南)添加。
3. 命令行部署用户同步代码、执行 `npm install`，检查 `wrangler.toml` 后运行 `npm run deploy`。如果 `origin` 指向自己的独立部署仓库，需先同步上游代码。
4. 刷新网页，确认版本为 `1.13.0`，检查账户和显示设置。手动安装扩展的用户需更新扩展文件并重新加载；商店安装的扩展按商店发布进度更新。

本次没有新增 Durable Object 迁移，也没有更改后端 API 或账户存储格式。从 `1.12.0` 升级继续使用现有数据，可以在 Cloudflare Dashboard 回滚到 `1.12.0`。从 `1.11.0` 之前升级，或回滚到 `1.11.0` 之前，仍需遵循[部署与回滚指南](https://github.com/wuzf/2fa/blob/v1.13.0/docs/DEPLOYMENT.md)中的迁移和暂停写入要求。
