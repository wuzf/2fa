**คุณสมบัติหลัก:** สร้างรหัส TOTP/HOTP อัตโนมัติ · เพิ่มคีย์ด้วยการสแกน QR Code/อ่านจากรูปภาพ/วางภาพหน้าจอ/ลากและวางรูปภาพ · จัดเก็บข้อมูลด้วยการเข้ารหัส AES-GCM 256 บิต · นำเข้าหลายรายการจาก Google Authenticator, Aegis, 2FAS, Bitwarden และแอปอื่น ๆ · ส่งออกได้หลายรูปแบบ (TXT/JSON/CSV/HTML/QR Code สำหรับย้ายข้อมูล Google) · สำรองและกู้คืนข้อมูลอัตโนมัติ · ซิงค์ข้อมูลสำรองระยะไกลผ่าน WebDAV/S3/OneDrive/Google Drive · ตั้งค่าความปลอดภัย/การซิงค์/การใช้งาน · รองรับ 15 ภาษาทั่วทั้งโครงการ (ตรวจหาอัตโนมัติ/เลือกเอง) · ธีมสว่าง/มืด/ตามระบบ · UI ที่ปรับตามขนาดหน้าจอและได้รับแรงบันดาลใจจาก Fluent 2

เว็บแอป ส่วนขยายเบราว์เซอร์ การตั้งค่าเริ่มต้น หน้า OTP สาธารณะ ข้อความ API และเอกสารสำรองข้อมูล รองรับภาษาจีนตัวย่อ จีนตัวเต็ม อังกฤษ ญี่ปุ่น เกาหลี เยอรมัน ฝรั่งเศส สเปน โปรตุเกส (บราซิล) อิตาลี รัสเซีย ตุรกี อินโดนีเซีย เวียดนาม และไทย อินเทอร์เฟซจะใช้ภาษาตามเบราว์เซอร์หรือภาษาที่เลือกเอง และใช้ภาษาอังกฤษหากไม่รองรับภาษาของเบราว์เซอร์ สามารถนำเข้าไฟล์สำรอง CSV/HTML ได้แม้อินเทอร์เฟซจะใช้ภาษาต่างจากตอนสร้างไฟล์

## 🧩 ส่วนขยายเบราว์เซอร์

ติดตั้ง 2FA Verification Assistant: **[Chrome Web Store](https://chromewebstore.google.com/detail/2fa-%E9%AA%8C%E8%AF%81%E5%8A%A9%E6%89%8B/lifeiloiefdlbohelpjajdbopeocalhl)** · **[Microsoft Edge Add-ons](https://microsoftedge.microsoft.com/addons/detail/kmchncmoddhdlbpfoejeahdjhieghklm)** · **[Firefox Add-ons](https://addons.mozilla.org/zh-CN/firefox/addon/2fa-%E9%AA%8C%E8%AF%81%E5%8A%A9%E6%89%8B/)**

เปิดลิงก์ติดตั้งในเบราว์เซอร์ที่ตรงกัน หลังติดตั้ง ให้ป้อน URL ของอินสแตนซ์ 2FA ที่คุณโฮสต์เองในการตั้งค่าส่วนขยาย แล้วลงชื่อเข้าใช้อินสแตนซ์นั้นในเบราว์เซอร์เดียวกัน เพื่อดู คัดลอก และกรอกรหัส TOTP การกรอกอัตโนมัติต้องได้รับสิทธิ์สำหรับแต่ละเว็บไซต์ ซึ่งให้ได้ตั้งแต่ครั้งแรกที่กรอกรหัสบนเว็บไซต์นั้น ส่วนขยายต้องใช้อินสแตนซ์ที่ติดตั้งใช้งานจากโครงการนี้ และรองรับอินเทอร์เฟซทั้ง 15 ภาษาที่ระบุข้างต้น Firefox บนเดสก์ท็อปและ Android ต้องเป็นเวอร์ชัน 153 ขึ้นไปและใช้แท็บปกติ ไม่รองรับแท็บคอนเทนเนอร์บนเดสก์ท็อปและแท็บส่วนตัวบนทั้งสองแพลตฟอร์ม ร้านค้าส่วนขยายรองรับ Firefox บน Android ตั้งแต่เวอร์ชัน 1.2.0 แต่ยังไม่ได้ทดสอบด้วยอุปกรณ์จริง Firefox บน Android ไม่มีแป้นพิมพ์ลัดสำหรับส่วนขยาย

## 🚀 ติดตั้งใช้งานอย่างรวดเร็ว

### เว็บไซต์สาธิต

เข้าใช้งานเว็บไซต์สาธิต (รหัสผ่าน `2fa-Demo.`): **[https://2fa-dev.wzf.workers.dev](https://2fa-dev.wzf.workers.dev)**

### ติดตั้งด้วยคลิกเดียว (แนะนำ)

[![ติดตั้งบน Cloudflare Workers](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/wuzf/2fa)

> แนะนำให้ติดตั้งด้วยคลิกเดียว ผู้ใช้ทุกคนควรอัปเกรดระบบเดิมผ่านเวิร์กโฟลว์ **Sync Upstream** อย่าอัปเกรดด้วยการลบ Worker ลบที่เก็บโค้ด หรือติดตั้งใหม่

1. คลิกปุ่มด้านบน ลงชื่อเข้าใช้ด้วย GitHub และอนุญาตการเข้าถึง
2. ลงชื่อเข้าใช้บัญชี Cloudflare คลิก **Deploy** แล้วรอจนติดตั้งเสร็จ (ระบบจะสร้างพื้นที่จัดเก็บ KV ให้อัตโนมัติ)
3. เปิด URL ของ Workers ที่ Cloudflare ให้มา **ตั้งรหัสผ่านผู้ดูแลระบบ** แล้วเริ่มใช้งาน

> การสร้างอัตโนมัติจาก Git จะใช้ `wrangler.toml` ในที่เก็บโค้ดโดยตรง การตั้งค่าปัจจุบันประกาศ `SECRETS_KV` ไว้อย่างชัดเจน โดย Wrangler จะสร้าง KV ที่ต้องใช้ให้อัตโนมัติในการติดตั้งครั้งแรก และใช้ทรัพยากรที่ผูกกับ Worker ปัจจุบันต่อในการติดตั้งครั้งถัดไป
> หากคุณตั้งค่าคำสั่งสร้างจาก Git เองใน Cloudflare Dashboard **ให้ใช้ `npm run deploy` เป็นคำสั่งติดตั้ง แทนการเรียก `npx wrangler deploy` โดยตรง** เพื่อคงขั้นตอนใส่ข้อมูลเวอร์ชันและให้สอดคล้องกับวิธีติดตั้งเริ่มต้นของที่เก็บโค้ด

#### แนะนำ: เปิดใช้การเข้ารหัสข้อมูล

หลังติดตั้ง ให้เพิ่ม Secret ชื่อ `ENCRYPTION_KEY` ที่ **Cloudflare Dashboard → Worker → Settings → Variables**:

```bash
# Generate encryption key (choose one)
openssl rand -base64 32
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

> `ENCRYPTION_KEY` คือคีย์หลักสำหรับถอดรหัสข้อมูลที่มีอยู่ **แนะนำให้ตั้งค่า** โดยต้องบันทึกค่าต้นฉบับไว้ในโปรแกรมจัดการรหัสผ่าน ข้อมูลสำรองออฟไลน์ หรือสถานที่ปลอดภัยอื่นทันที
>
> หากไม่มั่นใจว่าจะเก็บค่าต้นฉบับไว้ได้ **การไม่ตั้งค่าเลยดีกว่าตั้งค่าแล้วทำคีย์หาย**:
>
> - เมื่อตั้งค่าแล้ว: รายการคีย์ ข้อมูลสำรองอัตโนมัติ และข้อมูลรับรอง WebDAV/S3/OneDrive/Google Drive จะถูกเข้ารหัสทั้งหมด
> - หากคีย์สูญหาย: Cloudflare จะไม่แสดงค่าต้นฉบับให้ดูอีก และจะไม่สามารถอ่านหรือกู้คืนข้อมูลและข้อมูลสำรองที่เข้ารหัสไว้ได้
> - การทำงานปัจจุบัน: เมื่อตรวจพบข้อมูลที่เข้ารหัสแต่ไม่มี `ENCRYPTION_KEY` ระบบจะล็อกการอ่านและเขียน เพื่อป้องกันการเขียนทับข้อมูลเดิมโดยไม่ได้ตั้งใจ

#### อัปเดตเวอร์ชัน

การติดตั้งด้วยคลิกเดียวจะสร้างที่เก็บโค้ดอิสระ ไม่ใช่ Fork การอัปเกรดจะทำกับระบบเดิมผ่านเวิร์กโฟลว์ **Sync Upstream**

> ⚠️ **สำรองข้อมูลก่อนอัปเกรดเสมอ**: ก่อนอัปเดตเวอร์ชัน ให้ส่งออกข้อมูลปัจจุบันผ่าน **ส่งออกหลายรายการ** หรือ **กู้คืนการตั้งค่า → ส่งออกข้อมูลสำรอง** เพื่อป้องกันข้อมูลสูญหายหากการอัปเดตล้มเหลว

1. เปิดที่เก็บโค้ด 2fa ที่สร้างในบัญชี GitHub ของคุณระหว่างการติดตั้งด้วยคลิกเดียว
2. ไปที่ **Actions** → **Sync Upstream**
3. คลิก **Run workflow** คงค่าแบรนช์ต้นทางเป็น `main` ตามค่าเริ่มต้น แล้วเริ่มการรันใหม่
4. รอให้การซิงค์และการติดตั้งอัตโนมัติของ Cloudflare เสร็จ จากนั้นรีเฟรชแอป

เวิร์กโฟลว์จะรักษาชื่อ Worker การผูก KV และการตั้งค่าการติดตั้งทั่วไปของที่เก็บโค้ดคุณไว้โดยอัตโนมัติ แล้วติดตั้งใหม่บน **Worker เดิม** รวมถึงเก็บไฟล์เวิร์กโฟลว์ที่มีอยู่ในที่เก็บโค้ดไว้ด้วย

> **หากไม่พบ Sync Upstream**: การติดตั้งแบบคลิกเดียวจะไม่คัดลอก `.github/workflows` ตอนนำเข้าที่เก็บโค้ด ที่เก็บโค้ดที่สร้างใหม่จึงไม่มีเวิร์กโฟลว์ และต้องเพิ่มจุดเริ่มต้นนี้ก่อนอัปเกรดครั้งแรก ให้แทนที่ `OWNER/REPO` ในลิงก์ด้านล่างด้วยที่เก็บโค้ดของคุณ (เช่น `alice/2fa`) แล้วเปิดในเบราว์เซอร์ GitHub จะกรอกชื่อไฟล์และเนื้อหาให้ จากนั้นคลิก **Commit changes**:
>
> ```text
> https://github.com/OWNER/REPO/new/main?filename=.github/workflows/sync-upstream.yml&value=%23%20Save%20as%20.github%2Fworkflows%2Fsync-upstream.yml%20in%20your%20repository.%0A%23%20The%20upgrade%20steps%20come%20from%20wuzf%2F2fa%2C%20so%20this%20file%20never%20needs%20updating.%0Aname%3A%20Sync%20Upstream%0A%0Aon%3A%0A%20%20workflow_dispatch%3A%0A%20%20%20%20inputs%3A%0A%20%20%20%20%20%20upstream_ref%3A%0A%20%20%20%20%20%20%20%20description%3A%20Upstream%20branch%20or%20tag%20to%20sync%0A%20%20%20%20%20%20%20%20required%3A%20false%0A%20%20%20%20%20%20%20%20default%3A%20main%0A%0Apermissions%3A%0A%20%20contents%3A%20write%0A%0Ajobs%3A%0A%20%20sync%3A%0A%20%20%20%20uses%3A%20wuzf%2F2fa%2F.github%2Fworkflows%2Fsync-upstream.yml%40main%0A%20%20%20%20with%3A%0A%20%20%20%20%20%20upstream_ref%3A%20%24%7B%7B%20inputs.upstream_ref%20%7D%7D%0A
> ```
>
> หรือจะสร้าง `.github/workflows/sync-upstream.yml` เองแล้วคัดลอกเนื้อหาจาก <https://github.com/wuzf/2fa/blob/main/.github/sync-upstream-entry.yml> ก็ได้ จุดเริ่มต้นนี้มีเพียงไม่กี่บรรทัด ขั้นตอนอัปเกรดดึงมาจากที่เก็บโค้ดต้นทาง จึงไม่ต้องแก้ไขอีก จากนั้นทำตามขั้นตอนอัปเกรดด้านบน

> **หากการอัปเกรดก่อนหน้านี้ล้มเหลวด้วยข้อความ `without workflows permission`**: หลังจากเผยแพร่การแก้ไขไปยัง `main` ของต้นทางแล้ว เวิร์กโฟลว์ **Sync Upstream** เดิมที่มีขั้นตอนรวมการตั้งค่าการติดตั้งอัตโนมัติจะอัปเกรดตามขั้นตอนด้านบนได้ โดยไม่ต้องแก้ YAML หรือตั้งค่า PAT ให้เริ่มการรันใหม่ด้วย `main` เพราะแท็กรีลีสเก่ายังไม่มีการแก้ไขนี้ สำหรับกรณีอื่น ดู[การแก้ปัญหาการอัปเกรด](../DEPLOYMENT.md#升级故障排查) (ภาษาจีน)

วิธีนี้ไม่กระทบ Worker การผูก KV หรือ Secrets ที่มีอยู่ **หากตั้งค่า `ENCRYPTION_KEY` แล้ว ไม่ต้องป้อนใหม่ระหว่างอัปเกรด และหากยังไม่ได้ตั้งค่า ก็ยังใช้ขั้นตอนอัปเกรดนี้ได้**

> ⚠️ `ENCRYPTION_KEY` คือคีย์หลักสำหรับถอดรหัสข้อมูลที่มีอยู่ โปรดบันทึกไว้ในโปรแกรมจัดการรหัสผ่านเมื่อสร้างครั้งแรก Cloudflare Secrets ไม่สามารถแสดงค่าได้หลังบันทึก การอัปเกรดตามปกติไม่ต้องป้อนคีย์ใหม่ แต่หากลบคีย์โดยไม่ได้เก็บค่าต้นฉบับไว้ จะไม่สามารถกู้คืนข้อมูลที่เข้ารหัสอยู่ได้

> ⚠️ **การย้อนกลับไปใช้เวอร์ชันก่อน 1.8.0**: ตั้งแต่ 1.8.0 เป็นต้นมา การเพิ่มค่าตัวนับ HOTP จะถูกเก็บแยกจากข้อมูลหลัก ก่อนย้อนเวอร์ชัน ให้เรียกเอนด์พอยต์ compaction หนึ่งครั้งเพื่อเขียนค่าตัวนับกลับเข้าไป มิฉะนั้นตัวนับ HOTP จะกลับไปเป็นค่า ณ ตอนอัปเกรด ดู[ขั้นตอนย้อนเวอร์ชัน](../DEPLOYMENT.md#回滚到-180-之前的版本) (ภาษาจีน) ระบบที่ใช้เฉพาะ TOTP จะไม่ได้รับผลกระทบ

#### ตรวจสอบผลการรวมการเปลี่ยนแปลง

เวิร์กโฟลว์ `Sync Upstream` ออกแบบให้อัปเกรดเสร็จบน **ที่เก็บโค้ดเดิมและ Worker เดิม** เสมอ ปัจจุบันเวิร์กโฟลว์จะรวม `wrangler.toml` ให้อัตโนมัติและแสดงความแตกต่างจากต้นทางในหน้าสรุป เพื่อให้ตรวจสอบได้ว่าค่าใดมาจากการตั้งค่าการติดตั้งของคุณ

1. ตรวจสอบความแตกต่างของ `wrangler.toml` ในหน้าสรุปการรัน GitHub Actions
2. เปิด `wrangler.toml` ในที่เก็บโค้ดของคุณ
3. ตรวจสอบว่าชื่อ Worker การผูก KV เส้นทาง และการตั้งค่าการติดตั้งเดิมยังถูกต้อง
4. หากคุณมีการตั้งค่า `wrangler.toml` เฉพาะทาง ให้คอมมิตเพิ่มเติมตามความจำเป็น

> หาก Cloudflare ไม่เริ่มติดตั้งใหม่โดยอัตโนมัติ ให้ไปที่หน้า **Deployments** แล้วติดตั้งจากคอมมิตล่าสุดของที่เก็บโค้ดปัจจุบันอีกครั้ง อย่าลบแล้วติดตั้งใหม่

## 📖 คู่มือการใช้งาน

### เพิ่มคีย์

คลิกปุ่มลอย **➕** ที่มุมขวาล่าง:

- **สแกน QR Code** — ใช้กล้องสแกน QR Code ของ 2FA เพื่อกรอกข้อมูลอัตโนมัติ
- **เลือกรูปภาพ** — อัปโหลดภาพหน้าจอ QR Code เพื่ออ่านข้อมูลอัตโนมัติ
- **วางภาพหน้าจอ** — กด Ctrl+V เพื่อวางภาพหน้าจอ QR Code จากคลิปบอร์ด (สะดวกสำหรับผู้ใช้พีซีที่ไม่มีกล้อง)
- **ลากและวางรูปภาพ** — ลากภาพ QR Code ลงในกล่องโต้ตอบโดยตรงเพื่ออ่านข้อมูลอัตโนมัติ
- **เพิ่มด้วยตนเอง** — ป้อนชื่อบริการและคีย์ลับ Base32 (ขยายการตั้งค่าขั้นสูงเพื่อปรับจำนวนหลัก/ช่วงเวลา/อัลกอริทึม)

### การใช้งานประจำวัน

- **คัดลอกรหัส**: คลิกตัวเลขรหัสโดยตรง
- **จัดการคีย์**: คลิก **⋯** ที่มุมขวาบนของการ์ด → ดู QR Code / คัดลอก URI / คัดลอกลิงก์หน้า / แก้ไข / ลบ
- **ค้นหา**: ค้นหาด้วยชื่อบริการหรือชื่อบัญชีในช่องค้นหาด้านบนแบบเรียลไทม์
- **จัดกลุ่มอัจฉริยะ**: จัดกลุ่มบริการที่เกี่ยวข้องและหลายบัญชีโดยอัตโนมัติ พร้อมตัวเลือกกลับไปแสดงรายการแบบไม่จัดกลุ่ม
- **เรียงลำดับ**: เรียงตามเวลาที่เพิ่มหรือชื่อ
- **ธีม**: ปุ่มลอย → **การตั้งค่า → การตั้งค่าการใช้งาน → โหมดธีม** แล้วเลือกสว่าง มืด หรือตามระบบ

### นำเข้าหลายรายการ

คลิกปุ่มลอย → **📥 นำเข้าหลายรายการ** รองรับการนำเข้าไฟล์หรือวางข้อความ

| แหล่งที่มา             | รูปแบบ                                            |
| ---------------------- | ------------------------------------------------- |
| ทั่วไป                 | ข้อความ URI `otpauth://` (TXT), CSV, HTML         |
| Google Authenticator   | QR Code สำหรับย้ายข้อมูล (`otpauth-migration://`) |
| Aegis                  | ไฟล์ส่งออก JSON                                   |
| 2FAS                   | ไฟล์ส่งออก `.2fas`                                |

| andOTP                 | ไฟล์ส่งออก JSON                                   |
| Ente Auth              | ไฟล์ส่งออก                                        |

### ส่งออกหลายรายการ

คลิกปุ่มลอย → **📤 ส่งออกหลายรายการ** รองรับรูปแบบ TXT, JSON, CSV, HTML รวมถึงการสร้าง **QR Code สำหรับย้ายข้อมูล Google Authenticator** (สแกนเพื่อนำเข้าได้โดยตรง)
การส่งออกมาตรฐาน TXT / JSON / CSV / HTML จะใช้รูปแบบเดียวกันจากแบ็กเอนด์เป็นหลักขณะออนไลน์ และเปลี่ยนไปใช้การส่งออกภายในเครื่องที่เข้ากันได้โดยอัตโนมัติเมื่อออฟไลน์หรือเนื้อหาคำขอมีขนาดใหญ่เกินไป

### สำรองและกู้คืนข้อมูล

ระบบจะสำรองข้อมูลอัตโนมัติเมื่อข้อมูลเปลี่ยนแปลงและเมื่อถึงรอบตรวจสอบประจำวัน โดยเก็บข้อมูลสำรองล่าสุด 100 ชุด (ปรับได้ในการตั้งค่า)
ไฟล์สำรองใหม่จะใช้รูปแบบตาม **การตั้งค่า → รูปแบบการส่งออกเริ่มต้น** ข้อมูลสำรองระยะไกลแบบอัตโนมัติก็ใช้นามสกุลเดียวกัน (`txt`, `json`, `csv` หรือ `html`)

คลิกปุ่มลอย → **🔄 กู้คืนการตั้งค่า** เพื่อดูรายการสำรอง แสดงตัวอย่างเนื้อหา กู้คืน หรือส่งออก นอกจากนี้ยังอัปโหลดไฟล์ `backup_*.(txt|json|csv|html)` ที่ดาวน์โหลดจาก WebDAV/S3/OneDrive/Google Drive เพื่อดูตัวอย่างและกู้คืนได้

#### สำรองข้อมูลระยะไกล

รองรับการซิงค์ข้อมูลสำรองไปยังพื้นที่จัดเก็บระยะไกล โดยส่งให้อัตโนมัติเมื่อข้อมูลเปลี่ยนแปลง และตั้งค่าปลายทางสำรองได้หลายแห่ง:

- **WebDAV** — รองรับคลาวด์ไดรฟ์หรือบริการที่โฮสต์เองซึ่งใช้โปรโตคอล WebDAV มาตรฐาน (⚠️ ไม่รองรับบริการที่ผ่านพร็อกซี Cloudflare เช่น Nutstore/jianguoyun ซึ่งทำให้เกิดข้อผิดพลาดลูป 520)
- **พื้นที่จัดเก็บที่เข้ากันได้กับ S3** — รองรับ AWS S3, Cloudflare R2, MinIO, Alibaba Cloud OSS และบริการอื่นที่เข้ากันได้กับ S3
- **OneDrive** — หลังอนุญาตผ่าน Microsoft OAuth ข้อมูลสำรองจะถูกเขียนลงในโฟลเดอร์ย่อยภายในโฟลเดอร์เฉพาะของแอปบน OneDrive
- **Google Drive** — หลังอนุญาตผ่าน Google OAuth ข้อมูลสำรองจะถูกเขียนลงในโฟลเดอร์ Google Drive ที่กำหนดไว้

เพิ่มและจัดการปลายทางสำรองข้อมูลระยะไกลได้ที่ **การตั้งค่า → การตั้งค่าการซิงค์**

ข้อมูลสำรองระยะไกลจะเก็บเนื้อหาเดียวกับข้อมูลสำรองที่แอปสร้าง หากตั้งค่า `ENCRYPTION_KEY` ไว้ตอนสร้างข้อมูลสำรอง ไฟล์ระยะไกลก็จะเป็นข้อมูลที่เข้ารหัสเช่นกัน การกู้คืนต้องใช้ `ENCRYPTION_KEY` ค่าเดิมที่เก็บอยู่ใน Worker

ขั้นตอนตั้งค่าโดยละเอียด: [การตั้งค่าคลาวด์ไดรฟ์](../CLOUD_DRIVE_SETUP.md) (ขณะนี้เป็นภาษาจีน)

### การตั้งค่า

คลิกปุ่มลอย → **⚙️ การตั้งค่า**:

- **เปลี่ยนรหัสผ่าน** — เปลี่ยนรหัสผ่านผู้ดูแลระบบ
- **โหมดธีม** — เลือกสว่าง มืด หรือตามระบบ
- **ภาพเคลื่อนไหวขณะเปลี่ยนรหัส** — ปิดภาพเคลื่อนไหว หรือเลือกแบบไหล พลิก หรือสปอตไลต์
- **ระยะเวลาที่เข้าสู่ระบบได้** — กำหนดเวลาหมดอายุของ JWT
- **รูปแบบการส่งออกเริ่มต้น** — กำหนดตัวเลือกเริ่มต้นสำหรับการส่งออก รวมถึงนามสกุลไฟล์ของข้อมูลสำรองใหม่และข้อมูลสำรองระยะไกลแบบอัตโนมัติ
- **จำนวนข้อมูลสำรองที่เก็บ** — ปรับจำนวนข้อมูลสำรองอัตโนมัติที่ต้องการเก็บ
- **สำรองข้อมูลระยะไกล** — ตั้งค่าปลายทางสำรอง WebDAV/S3/OneDrive/Google Drive
- **ออกจากระบบ** — ล้างคุกกี้เซสชันปัจจุบันและแคชภายในเครื่องด้วยคลิกเดียว โดยยังล้างข้อมูลภายในเครื่องได้แม้ติดต่อเซิร์ฟเวอร์ไม่ได้

### ติดตั้งเป็นแอปบนมือถือ (PWA)

- **iOS**: เปิดใน Safari → ปุ่มแชร์ → เพิ่มไปยังหน้าจอโฮม
- **Android**: เปิดใน Chrome → เมนู (⋮) → เพิ่มลงในหน้าจอหลัก

หลังติดตั้ง สามารถใช้แบบเต็มหน้าจอเหมือนแอปทั่วไป และรองรับการเข้าถึงแบบออฟไลน์

### กรอก TOTP ใน Chrome / Edge / Firefox

คลิกส่วนขยายเพื่อเลือกบัญชี หรือกด `Ctrl+Shift+U` เพื่อกรอก TOTP ปัจจุบันของบัญชีที่เชื่อมไว้ก่อนแล้ว เมื่อเว็บไซต์ได้รับสิทธิ์แล้ว ส่วนขยายจะตรวจพบและกรอกช่องรหัสยืนยันของเว็บไซต์นั้นให้อัตโนมัติ หากพบหลายบัญชีที่ตรงกันจะแสดงตัวเลือกบัญชี รองรับทั้งช่องเดียวและช่องแยก 6/8 หลัก และจะไม่ส่งฟอร์มให้

หลังลงชื่อเข้าใช้อินสแตนซ์ 2FA ด้วยโปรไฟล์เบราว์เซอร์เดียวกันและอนุญาตการเข้าถึงอินสแตนซ์แล้ว คุณสามารถปิดแท็บของอินสแตนซ์ได้ ตามค่าเริ่มต้น ส่วนขยายจะอ่านคีย์ลับผ่านเซสชันที่ยังใช้งานได้ และคำนวณรหัสในหน่วยความจำเบื้องหลังสำหรับแต่ละงาน เมื่อเซสชันหมดอายุให้ลงชื่อเข้าใช้อีกครั้ง หากเปิดใช้โหมดออฟไลน์อย่างชัดเจน ระบบจะบันทึกแคชคีย์ลับแยกไว้ภายในเครื่อง ทำให้ใช้รหัสได้แม้ไม่มีการเชื่อมต่อเครือข่ายหรือไม่ได้เปิดแท็บอินสแตนซ์ แคชนี้ไม่มีการเข้ารหัสด้วยรหัสผ่านเพิ่มเติม โค้ดส่วนขยายที่ได้รับอนุญาตสามารถอ่านรายการคีย์ลับทั้งหมดได้ แต่คีย์ลับจะไม่ถูกส่งไปยังหน้าต่างป๊อปอัปหรือเว็บไซต์ปลายทาง รองรับช่องข้อมูลใน Shadow DOM แบบเปิดและ iframe ที่มีต้นทางเดียวกัน ไม่รองรับ HOTP, iframe ข้ามต้นทาง, Shadow DOM แบบปิด และการท่องเว็บแบบส่วนตัว

ดู[คู่มือติดตั้งและใช้งาน](../BROWSER_EXTENSION.md), [ประกาศความเป็นส่วนตัวสำหรับ Chrome / Edge](../../extension/PRIVACY.md) และ[ประกาศความเป็นส่วนตัวสำหรับ Firefox](../../extension/PRIVACY_FIREFOX.md) (ขณะนี้เป็นภาษาจีน)

## 🔒 ความปลอดภัย

- **รหัสผ่าน**: ใช้แฮช PBKDF2-SHA256 พร้อม salt (100,000 รอบ) และเก็บ JWT ในคุกกี้แบบ HttpOnly + Secure + SameSite=Strict
- **การเข้ารหัสข้อมูล**: เมื่อตั้งค่า `ENCRYPTION_KEY` คีย์ลับ ข้อมูลสำรอง และข้อมูลรับรอง WebDAV/S3/OneDrive/Google Drive ทั้งหมดจะเข้ารหัสด้วย AES-GCM 256 บิต โปรดเก็บคีย์ต้นฉบับให้ดี เพราะหากสูญหายจะถอดรหัสข้อมูลที่เข้ารหัสไว้ไม่ได้
- **การรับส่งข้อมูล**: ใช้ HTTPS ตลอดเส้นทาง และ TLS 1.2+
- **ความเป็นส่วนตัว**: สร้าง OTP ฝั่งไคลเอนต์ ไม่เก็บข้อมูลการใช้งาน และเปิดเผยซอร์สโค้ดทั้งหมด
- **ระยะเวลาที่เข้าสู่ระบบได้**: ค่าเริ่มต้น 30 วัน ปรับได้ในการตั้งค่า และต่ออายุอัตโนมัติระหว่างใช้งาน (ต่ออายุเมื่อเหลือน้อยกว่า 7 วัน)

## 🔗 API สำหรับ OTP สาธารณะ

สร้างรหัสยืนยันผ่าน URL ได้โดยตรงโดยไม่ต้องลงชื่อเข้าใช้:

```
https://your-worker.workers.dev/otp/YOUR_SECRET_KEY
https://your-worker.workers.dev/otp/YOUR_SECRET_KEY?digits=8&period=60
https://your-worker.workers.dev/otp/YOUR_SECRET_KEY?type=hotp&counter=5
```

พารามิเตอร์: `type` (totp/hotp), `digits` (6/8), `period` (30/60/120), `algorithm` (sha1/sha256/sha512), `counter` (สำหรับ HOTP)

หน้า TOTP แสดงทั้งรหัสปัจจุบันและรหัสถัดไป ซึ่งคัดลอกได้ทั้งคู่ และอัปเดตในหน้าเดิมเมื่อสิ้นสุดช่วงเวลา หน้า HOTP ใช้ค่าตัวนับที่ระบุในลิงก์ การคัดลอกจะไม่เพิ่มค่าตัวนับ
