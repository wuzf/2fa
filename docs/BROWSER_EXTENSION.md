# Chrome / Edge / Firefox 验证码辅助填充

“2FA 验证助手”连接你自行部署的 2FA 实例，在浏览器中查看、复制和填充 TOTP 验证码。支持手动填充、快捷键，以及按验证页面授权的自动填充。

## 安装与连接

| 浏览器  | 官方安装入口                                                                                                                          |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Chrome  | [Chrome 应用商店](https://chromewebstore.google.com/detail/2fa-%E9%AA%8C%E8%AF%81%E5%8A%A9%E6%89%8B/lifeiloiefdlbohelpjajdbopeocalhl) |
| Edge    | [Microsoft Edge Add-ons](https://microsoftedge.microsoft.com/addons/detail/kmchncmoddhdlbpfoejeahdjhieghklm)                          |
| Firefox | [Firefox 附加组件商店](https://addons.mozilla.org/zh-CN/firefox/addon/2fa-%E9%AA%8C%E8%AF%81%E5%8A%A9%E6%89%8B/)                      |

1. 使用对应浏览器打开商店页面，点击“添加至 Chrome”、“获取”或“添加到 Firefox”，并将扩展固定到工具栏。
2. 在扩展设置中输入自己的 2FA 实例地址，点击“连接 2FA”，批准对该实例的访问权限。尚未部署实例时，请先阅读[部署指南](DEPLOYMENT.md)。
3. 如提示登录，点击“去登录”，在同一浏览器的普通窗口中登录实例，再回到扩展设置完成连接。Firefox 请使用默认容器中的普通标签页。

远程实例使用 HTTPS，未填写协议时会自动补全。连接成功后可以关闭实例网页；默认模式仍需网络和有效登录会话。扩展支持自动检测和手动切换显示语言，建议使用当前稳定版桌面 Chrome、Edge 或 Firefox；Firefox 最低版本为 153，不支持容器标签页、隐私窗口或 Android。

## 查看、复制与填充

打开工具栏弹窗后，可搜索服务名、用户名或邮箱，也可选择“全部账户”。星标用于置顶常用账户。

- **复制**：点击账户卡片或当前验证码。下一组验证码也可单独复制，但须等标注的时间后生效。
- **填充**：在网站的验证码页面打开扩展，核对账户后点击“填充”。自动填充始终使用当前有效验证码。
- **记住账户**：复选框旁写明它对应的账户。弹窗打开时是列表第一个账户；点击卡片（同时会复制验证码）、用方向键或回车选中卡片，或把鼠标移到卡片的“填充”按钮上，都会改为该卡片。鼠标经过星标或卡片空白处、用 Tab 经过其他卡片的按钮时不会改变，所以移到复选框时显示的仍是最后选中的账户。未手动改动时，复选框显示该账户是否已记住；手动勾选或取消后，这个选择用于下一次填充，不随鼠标移动或焦点变化改变。勾选后完成手动填充，该账户会成为此网站记住的账户，替换之前记住的账户；在按登录邮箱区分账户的网站（例如 Google），无论页面是否显示邮箱，都只替换与该账户自身邮箱相同的已记住账户，不同邮箱可各自记住一个账户。取消勾选后再填充，会移除该账户的记忆。仅复制验证码不会保存绑定。
- **快捷键**：Windows / Linux 使用 `Ctrl+Shift+U`，macOS 使用 `Command+Shift+U`。无法唯一确定账户时，扩展会打开弹窗供选择。

出现多个验证码区域时，先点击正确的输入框，再打开扩展。无法识别时，可按提示确认使用已聚焦的输入框，或复制验证码后手动粘贴。登录密码框以及恢复码、备用码、优惠码、邮编等字段不会被填充，写明“不是验证器中的验证码”或“验证器设置时保存的恢复码”的恢复码框确认后也不会填充；以密码形式遮盖的验证码框按普通验证码框处理，同时写明验证器验证码和备用码的输入框（如“Auth/Backup Code”“应用中的验证码或备用码”），需按提示确认使用已聚焦的输入框后才会填充。

以下情况扩展会把输入框视为可能的短信或邮件验证码，需要先点击输入框再填充：

- **重发按钮**：输入框所在的卡片、表单或区块里有“重新发送”“重新获取验证码”“Resend”“Send me a new code”一类按钮，或发送后只剩“59s”一类倒计时（被禁用的按钮，或类名含 send、resend 的按钮上只剩“59”“00:59”也算），不论是否写明短信或邮件。输入框所在表单外、同一层区块里的重发按钮和倒计时也计入（如表单下方单独的“收不到？重新发送”），那里的首次发送按钮，以及页头、导航和页脚里的链接不计入。“重新获取二维码”“重新获取恢复码”“Resend QR code”这类重新获取二维码、恢复码、备用码或密钥的按钮不算重发。

- **已发送的说明**：说明或标题写明验证码已发送，包括不写渠道的“我们已向你发送 6 位验证码”，写明验证码已发送到脱敏的号码或邮箱（如 `138****1234`、`j***@example.com`），请用户查看短信或收件箱（如“请查看手机短信”“请查看邮箱中的验证码”“Check your inbox”），以及用将来时说明即将发送的（如“We'll text you a code”“You'll get a code by email”“我们会把验证码发给您”）。同一句里既写明已发送、又提出可改用其他方式（如“验证码已发送至您的邮箱，也可使用恢复码登录”）时，已发送的部分仍然计入；写明验证码也已发送到别处的（如“We've also sent the code to your email”）同样计入。通用验证码框旁只写了可改用短信或邮件接收（如“也可以通过邮箱接收验证码”），页面又没有任何身份验证器线索时，同样按短信或邮件验证码处理。

- **首次发送按钮**：“获取验证码”“Send code”一类按钮（包括用文字或 span 做的按钮）位于输入框自己的表单、紧邻区块或挑战卡片内。手机号所在行里的“获取验证码”，以及它变成的倒计时和“重新发送”也算（“重新发送验证邮件”一类讲邮箱验证的除外）。没有卡片或表单时，首次发送按钮和它变成的倒计时在下文所说的读取范围内、页面布局容器之内都计入；按钮所在区块另有手机号、邮箱等输入框时，最多比紧邻区块再远一层。在带标题的页面区域或卡片里，页面除验证码框外没有手机号、邮箱等其他输入框时，首次发送按钮不论远近都计入。步骤条、标签栏和标题里的“获取验证码”不算发送按钮。

- **提示条**：卡片内提示条和页头里的重发按钮，只要提示条提到验证码、写明已发送、提到脱敏的号码或邮箱，或提醒查看垃圾邮件、垃圾箱（如“Check your spam folder.”“请查看垃圾箱”），也计入；提示条里只有重发按钮、文字是“收不到？”“Having trouble?”一类求助语时同样计入。没有标题元素的卡片里，“收不到？重新发送”一类提示后的重发同样计入。页头、横幅、role=alert 警示提示条、没有标题元素的卡片以及输入框所在表单旁边，讲账户邮箱验证的提示条（如“邮箱尚未验证”“请确认邮箱地址”“Your email is not confirmed”）里的重发不计入，但按钮自己写明验证码（如“Resend code”“重新发送验证码”）时仍计入；提醒核对邮箱地址是否正确、查看垃圾邮件的指引不算这类提示。

首次发送按钮视为备用方式、不影响自动填充的情况：字段自身的标签、占位文字，或当前验证区域的标题、图例写明身份验证器。以下都不算：切换条里的身份验证器页签；手风琴里其他验证方式的标题（状态类名如 open、active、is-open 写在前面也算同一组）；卡片内其他区块里带说明文字的小标题；输入框所在区块的标题或说明写明短信、邮件、手机等渠道时，其他区块里只有标题的小标题（如“短信验证”区块旁只有“身份验证器”标题的区块）。只在说明句里提到身份验证器（如“请输入身份验证器中的验证码”）时，只有“发送短信验证码”“Text me a code”这类写明渠道的按钮视为备用方式。只出现“App”字样的标签栏、切换条或下载推广，写明不接受身份验证器验证码的说明，以及把身份验证器当作另一种方式提出的说明（如“也可以使用身份验证器中的验证码”“You can also use a code from your authenticator app”“Authenticator codes also work here”），都不算提到身份验证器。

读取范围：没有标题元素的卡片（如带 card、panel 类名或短标题的容器，包括类名含 page、main、layout、site 但自带标题的“login-page”一类卡片）同样按卡片处理；页面顶栏（如 Vant 的导航栏）里只有返回、关闭、帮助一类按键和短标题时，这个标题同样算短标题，页面上还有手机号、邮箱等其他输入框时不算。带标题的 main 区域和带标题的页面布局容器里的说明、发送和重发按钮会计入。没有标题的 main、#app、#root、page、layout、site 类容器和含导航或面包屑的容器里，以及没有这类容器的普通布局里，输入框往上四层以内的发送和重发按钮都计入，但只算到页面布局容器为止（布局容器自己的子区块也算；只包一个元素、类名或 id 为 page、main、layout、app 一类的外壳同样是边界）。另一个带输入框的表单里的按钮不计入；带手机号、邮箱等其他输入框的区块里的按钮只在紧邻区块内计入，其中首次发送按钮和它的倒计时可再远一层。说明句不受这些限制。计算层数时，只包着输入框本身的普通外壳（如 Ant Design Mobile 表单项在输入框外套的几层 div）算作输入框的一部分；没有 form 元素时，类名为 adm-form、login-form 一类的容器按表单处理（form-item、form-group 一类字段外壳不算）。卡片外的站点横幅、页头和提示条（包括只放 logo 和链接的页头），推送通知说明，“在手机上的身份验证器中查看”一类说明，不提具体渠道的“我们不会发消息索要验证码”一类提醒，“通过邮件领取恢复码”一类说明，客服电话，以及“手机丢了？”“改用短信”一类链接不受影响。

准备填充时，输入框旁的发送或重发按钮换了文字或渠道（如“获取短信验证码”变成“60秒后重新获取”，或从短信改为邮件）不影响这次填充；说明句、说明式标题（如“请输入短信验证码”）或图例里写明的渠道变了，或者原本没有的发送按钮出现、唯一的发送按钮消失、出现新的已发送说明，这次填充会停下。

扩展不会主动点击提交按钮，但网站可能在验证码填完整后自行提交。浏览器内部页和其他禁止填充的页面仍可查看与复制验证码。

## 开启自动填充

1. 打开目标网站的验证码页面，点击扩展，在底部开启“在此页面自动填充”。
2. 接受浏览器对该网站的访问权限请求。
3. 后续访问同一验证页面时，扩展会检测空白验证码框：唯一可靠匹配时填入，多个候选时显示账户选择。

自动填充按网站和页面路径授权。域名、端口或路径不同，需要分别开启；只通过查询参数区分的页面会共用同一授权范围。浏览器授予的权限覆盖相应主机，扩展会进一步限制自动填充的页面。

自动填充只支持 HTTPS 页面和本机地址。`192.168.1.1` 这类私网或链路本地地址的 HTTP 页面在不同网络中可能是不同设备，因此只能手动填充；此前对这类页面开启的自动填充授权会被自动移除。在 HTTP 页面打开扩展时，“在此页面自动填充”显示为不可用，下方会直接说明这是 HTTP 页面、只能手动填充，账户的“填充”按钮照常可用。

记住账户与授权自动填充是两个独立选项。对于自定义服务，先手动选择账户并记住绑定，再开启自动填充。Google 验证页面可根据明确显示的当前邮箱匹配账户；无法确定时仍需手动选择。搜索结果只剩一个或将账户星标置顶，不会单独触发自动填充。

自动填充不会覆盖你已经输入的内容。同一页面路径在一次页面加载内只自动填入一次完整验证码。网站拒绝后，即使切到其他页面再回来，也不会再自动填充；请手动填充，或刷新页面后重试。在设置页“网站设置”中，可以停用某个页面的自动填充或删除账户绑定；这些操作不会删除实例中的账户。

## 离线使用

默认采用网页登录会话模式，密钥只在取码时临时处理。需要断网使用时，可在设置中主动开启“允许离线使用”，完成一次联网同步后在本地生成验证码。

| 模式         | 取码条件             | 密钥保存方式                   |
| ------------ | -------------------- | ------------------------------ |
| 网页登录会话 | 实例在线且登录有效   | 临时内存，不持久保存种子       |
| 允许离线使用 | 已建立当前实例的缓存 | 保存当前浏览器中的独立密钥副本 |

**离线缓存包含原始密钥，没有额外的密码加密，请仅在可信设备上启用。** 缓存建立后，关闭实例网页、断网或重启浏览器仍可取码。联网时扩展自动更新账户；如果服务器确认登录已失效，会清除缓存并提示重新登录。实例前的 Cloudflare 质询或拦截页面不算登录失效，只显示为无法连接，不会清除缓存。扩展后台重启后，如果本次浏览器会话中 15 分钟内校过时且系统时间没有倒退，会继续使用该校时结果，离线时不额外提示。联网时扩展会复核这一结果，缓存无需更新时只请求服务器时间；自动填充会先等待复核完成，最多约 3 秒。重启浏览器、校时超过 15 分钟或从网页恢复缓存后，扩展无法确认期间系统时间是否被调整，会在联网时重新校时，缓存无需更新时只请求服务器时间。联网校时进行中不提示，只有校时失败或仍无法确认时才提示确认系统时间。

如果尚无扩展缓存且连接失败，可按提示“从 2FA 网页恢复”，读取同一实例网页已有的缓存。没有可用网页缓存时，需要先联网登录并同步。

关闭“允许离线使用”、切换实例或撤销实例访问权限，会删除扩展的离线缓存。如果正在编辑实例地址，请先撤销地址修改，再关闭离线使用。主网页退出登录或清除站点数据不会直接删除扩展中的副本；断网期间也无法立即得知服务器上的账户删除、密码修改或撤销。

## 设置与多设备使用

扩展设置中的“显示语言”支持跟随浏览器，以及与网页一致的 15 种语言：简体中文、繁體中文、English、日本語、한국어、Deutsch、Français、Español、Português (Brasil)、Italiano、Русский、Türkçe、Bahasa Indonesia、Tiếng Việt、ไทย。未支持的浏览器语言使用英文。此偏好独立保存在当前浏览器，对所有已连接的 2FA 实例生效，并同步更新已打开的扩展弹窗、设置页和网页内自动填充提示；切换语言不会重新填充验证码。

每个浏览器使用一个包含全部语言的扩展安装包，无需按语言分别安装。浏览器扩展管理页面显示的名称、描述和快捷键说明随浏览器语言选择，扩展内部可手动切换语言。

实例地址可直接修改，也可选择最近使用的地址，点击“保存并连接”后生效。切换实例会清除当前离线缓存，各实例的网站绑定分别保留。

浏览器账号同步安装扩展不等于同步扩展配置。实例地址、账户绑定、收藏和离线缓存保存在当前浏览器，各设备需要分别配置并登录实例。

## 支持范围

| 能力                                                  | 支持情况                                     |
| ----------------------------------------------------- | -------------------------------------------- |
| TOTP                                                  | 6/8 位，SHA1/SHA256/SHA512，30/60/120 秒周期 |
| 验证码输入框                                          | 单框、分格输入，以及延迟出现的表单           |
| 嵌入页面中的输入框                                    | 同源 iframe 和开放 Shadow DOM                |
| 离线取码                                              | 需主动启用并先建立缓存                       |
| HOTP、Steam Guard                                     | 不支持                                       |
| 无痕 / InPrivate / Firefox 隐私窗口、跨浏览器配置共享 | 不支持                                       |
| Firefox 容器标签页、Android                           | 不支持                                       |
| 跨域 iframe、关闭的 Shadow DOM                        | 不支持                                       |

网站实现各不相同，无法填充时可复制后粘贴。只有明确授权的验证页面才启用自动检测，请核对网站与账户后使用。

## 权限与隐私

扩展使用当前标签页访问、脚本执行和本地存储权限，并在连接实例或开启网站自动填充时申请相应主机权限。Firefox 另使用剪贴板写入权限，供用户点击复制验证码，不读取剪贴板。默认不授权所有网站。

扩展会读取所配置实例的完整账户库，用于展示和计算验证码；原始密钥不会传给弹窗或目标网站。目标网页可以读取被填入的验证码，多账户选择面板也会展示该网站的候选账户名称和账号。扩展不包含广告、遥测或开发者中转服务。

服务图标由实例服务器代为获取：实例会依次请求 Google 图标服务、Yandex 图标服务和该服务域名本身，这些第三方因此会收到服务域名，但不会收到账户名、种子、验证码或登录凭据。

数据保存、网络请求及删除方式分别见[Chrome / Edge 隐私说明](../extension/PRIVACY.md)和[Firefox 隐私说明](../extension/PRIVACY_FIREFOX.md)。

## 更新、停用与故障排查

商店安装的扩展由浏览器负责更新。禁用扩展会停止运行并保留本地配置；卸载会删除扩展配置、绑定、收藏和离线缓存，不影响服务器中的账户。

| 提示或现象                 | 处理方法                                             |
| -------------------------- | ---------------------------------------------------- |
| 尚未连接或实例权限已撤销   | 在设置中重新连接并授权                               |
| 登录已失效                 | 点击“打开 2FA”，登录后返回扩展重试                   |
| 无法连接                   | 确认实例在线，检查地址及额外的访问认证               |
| 离线账户与网页不一致       | 恢复网络后等待更新，必要时在设置中重试连接           |
| 验证码或时间异常           | 校准系统时间，并在扩展中重试校时                     |
| 找不到输入框或出现多个候选 | 先聚焦正确输入框再试，或复制后粘贴                   |
| 页面已变化或请求过期       | 在最终验证码页面重新打开扩展                         |
| 列表中找不到账户           | 尝试搜索或“全部账户”，确认账户使用受支持的 TOTP 类型 |
| 快捷键无反应               | 在浏览器扩展快捷键设置中检查是否冲突                 |

Chrome 的快捷键设置位于 `chrome://extensions/shortcuts`，Edge 位于 `edge://extensions/shortcuts`。Firefox 打开 `about:addons`，点击齿轮菜单 →“管理扩展快捷键”。

反馈问题时请使用测试账户，不要提交真实密钥、验证码、管理密码或完整账户列表。

## 版本与运行依赖

扩展与主程序独立编号，不要求版本号相同。Chrome、Edge、Firefox 扩展版本均为 `1.1.1`。使用扩展前需要部署本项目的 2FA 服务并添加账户；扩展版本可在设置页查看。

## 从 GitHub Release 手动安装

每个 [GitHub Release](https://github.com/wuzf/2fa/releases) 都附带从该版本源码构建的安装包：`2fa-extension-chrome-<版本>.zip`、`2fa-extension-edge-<版本>.zip` 和 `2fa-extension-firefox-<版本>.zip`，版本为扩展自己的版本号。

- **Chrome / Edge**：解压安装包，在 `chrome://extensions` 或 `edge://extensions` 打开“开发者模式”，点击“加载已解压的扩展程序”（Edge 为“加载解压缩的扩展”），选择解压出的文件夹，也就是直接包含 `manifest.json` 的那一层。之后不要删除或移动这个文件夹。
- **Firefox**：安装包未经 Mozilla 签名，正式版 Firefox 只能临时载入。打开 `about:debugging#/runtime/this-firefox`，点击“临时载入附加组件”，直接选择 zip 文件；浏览器重启后需重新载入。长期使用请从商店安装。

手动安装的扩展不会自动更新，新版本需重新下载并在扩展管理页重新加载。Chrome / Edge 手动加载的扩展与商店版是两个扩展，分别保存设置，可以同时存在，但同一网站只应启用其中一个的自动填充。Firefox 安装包与商店版使用同一个附加组件 ID：已从商店安装时无需再临时载入；临时载入后，在浏览器重启前会代替商店版。

## 从源码构建

Chrome / Edge 在项目根目录执行：

```bash
npm ci
npm run build:extension
```

在浏览器扩展管理页开启“开发者模式”，选择“加载已解压的扩展程序”：Chrome 使用 `dist/extension/chrome`，Edge 使用 `dist/extension/edge`。更新源码后重新构建，再在扩展管理页重新加载。

Firefox 使用独立构建：

```bash
npm ci
node scripts/build-firefox-extension.js
```

打开 Firefox 的 `about:debugging#/runtime/this-firefox`，点击“临时载入附加组件”，选择 `dist/extension/firefox/manifest.json`。临时安装在浏览器重启后失效；更新源码后重新构建并点击“重新载入”。

开发结构与测试命令见[开发文档](DEVELOPMENT.md#浏览器扩展开发与测试)。
